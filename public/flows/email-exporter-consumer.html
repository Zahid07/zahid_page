email-exporter-consumer-python / Kafka → ClickHouse → S3 → email

How the exporter
is written, and how it works

A Python Kafka consumer that turns a store’s export request into a CSV (or XLSX) on S3-compatible storage and emails the merchant a download link. Three consumer entrypoints; one executor process per message.

01

The shape of the system

A merchant asks for a data export. Some other service publishes a JSON payload to a Kafka topic. This process is the consumer of that topic. It does not serve HTTP. It polls, filters, and for each accepted message it spawns app/kafkaConsumeExecutor.py as a subprocess. All of the export work lives in that subprocess.

Three facts about this shape drive the rest of the design:

The consumer does not do the work

consumer.py, consumer_queue.py, and consumer_batches.py only poll Kafka and spawn python app/kafkaConsumeExecutor.py --message '<json>'. Isolation is a process boundary, not a thread.

ClickHouse writes the file

The consumer never materialises the result set in Python for the main path. ClickHouse runs INSERT INTO FUNCTION s3(..., 'CSVWithNames') and this process only asks MinIO for a seven-day presigned GET URL.

Handlers are optional until they are not

PostgreSQL tracking is off unless PG_HOST is set. WebSocket progress and Optimus ID encoding exist as modules and are not imported by the executor. Redis lock failures are treated as “new export”. The pipeline prefers to continue.

02

End to end

Twelve stages from a Kafka record to an emailed link. Side systems (Redis, Postgres, Graylog, the CSV combiner) sit beside the happy path, they are not the path.

03

Three consumers, one executor

The Dockerfile copies consumer.py and consumer_batches.py and starts python consumer.py. consumer_queue.py is in the repo and is not in the image. All three use confluent_kafka.Consumer, auto.offset.reset: latest, and SASL_SSL + SCRAM-SHA-512 when WORKER_ENV is production or stage.

consumer_queue.py NUM_WORKER_THREADS (5) × fire-and-forget Popen Manual, after spawn (also on worker error) live, priority, test-email by WORKER_ENV No

The live flag

All three consumers do json_message.get("live", True). If the field is missing, the message is logged as a debug skip. Real export traffic has to set "live": false.

04

What the executor does

main(raw_message) in kafkaConsumeExecutor.py is the whole job. Handlers are constructed per process, not shared across messages. The order below is the order in the file.

01

Skip filters

may return

_apply_message_filters runs before any handler is built. Production drops is_test, parameters.is_test, or a subject containing "test". Development and stage drop everything that is not a test. If CONSUMER_WORKING_PRIORITY_ENABLED is true, only messages whose priority equals CONSUMER_WORKING_PRIORITY continue.

Gate consumer.py and consumer_batches.py do not apply these filters themselves. They still spawn the subprocess; the executor exits immediately.
02

Parse and normalise

Pydantic

MessageHandler.parse_message validates EventPayload: id (coerced to str), parameters, optional columns, subject, non-empty to[], colours, type (csv | xlsx, default csv), user_id, priority (default 1), locale (ar | en, default ar). An audit id AUDIT-{user_id}-{YYYYMMDDHHMMSS} is written onto the model and into the global ErrorHandler.

Preprocess: subject is .title()’d, emails lowercased, colour strings stripped.

03

Insert export_requests

optional

PostgresHandler.from_env() returns None without PG_HOST. When present it CREATE TABLE IF NOT EXISTS and inserts status queued. Every PG method swallows exceptions so a down database does not fail the export.

Schema mismatch The column id is declared uuid PRIMARY KEY. The value written is AUDIT-…, which is not a UUID. Inserts fail, are logged, and the rest of the pipeline continues without a row.
04

Redis lock / cache

15-minute window

Key: {prefix}{store_id}_{export_id}_{sha256(params)}. Prefix is export_ch: in production, otherwise export_ch1:. Four outcomes from check_export_lock — see the diagram in section 05.

05

Export

ClickHouse → S3

ParallelBatchHandler.execute is the only export entry. IDs 777777 (orders) and 888888 (order items) with both from_date and to_date split the range into 24 slices and run 6 at a time. Everything else — including products 100 — is a single run_write_query.

PG status moves to running before the query, then combining or emailing after.

06

Row-count gate

after the file exists

For orders and order items only, three count templates run: GET_ORDERS_DATA_COUNT_NEW, GET_DATA_COUNT (unfiltered total from curated_data.orders_data), GET_ORDER_ITEMS_DATA_COUNT_NEW. The active count is orders when id is 777777 and there is no product filter; otherwise order items.

skip_xlsx is true when that count exceeds MAX_XLSX_ROW_COUNT (default 200 000). is_large_export is true when total > 30 000 — and the executor never reads that flag. Batching was already decided in step 05 by id + date range.

07

CSV → XLSX

pandas

Only when type is xlsx and skip_xlsx is false. Download the presigned CSV, pd.read_csv → df.to_excel, upload to the hardcoded bucket exports, new 7-day URL, delete temp files. The unused _convert_to_xlsx still shells out to csv2xlsx.bin. The MinIO client here is constructed with secure=False regardless of the endpoint scheme.

08

Render and send

MJML

Jinja2 fills email.eta.html (RTL Arabic MJML: subject, body, logo, s3_url, store colours). POST {MJML_URL}/v1/render. Then EmailHandler.send_email.

The method that actually runs send_email is defined twice in emailHandlerClass.py. The second definition — SMTP to localhost:1025 (MailHog’s default in compose) — replaces the Mailgun/SES dispatcher. send_mailgun_email and send_ses_email exist and are not called from the executor.
09

Cache and log

side effects

On success: PG succeeded, Redis stores the file link under the lock key for 900 seconds, Graylog exported_successfully, email-message, and processingStats with ClickHouse / XLSX / email durations. Top-level exceptions become exporting_error.

05

Redis is a lock, then a cache

This is not a hash of the whole Kafka payload. The key is store, export type id, and a stable SHA-256 of parameters (sorted keys). Value "1" means in progress. Any other string is treated as a finished file link.

06

Single query vs 24 slices

LARGE_EXPORT_IDS = {"777777", "888888"}. If either date is missing, the handler logs a warning and falls back to one query. Dates that look like YYYY-MM-DD are parsed to a Unix timestamp; anything else is int(value).

The combine payload lists S3 keys (directory + filename, query string stripped), mode: "sync", callback: {kind: "none"}, and a reference_id equal to the audit id. Default URL: http://s3obj-materializer.tools.svc.cluster.local:8080, overridable with CSV_COMBINE_SERVICE_URL.

Zero successful batches → success=False, executor raises RuntimeError. Partial success plus a failed combine still returns success=True if any batch link exists.

07

Queries on disk

QueryHandler loads every .sql and .json under app/queries/ at init. Export type is the Kafka id, mapped by a hardcoded dict. Substitution is not Jinja. queryParser.Parser is a port of the TypeScript parser: required {{param}}, optional blocks [[ ... {{param}} ... ]] dropped when any inner param is missing, lists expanded to comma-separated quoted values.

08

Who does what

One class per concern, types in a sibling *Types.py. Almost every public method is wrapped in @error_handler.capture. The decorator increments a step counter, logs completion to Graylog, and on exception writes logs/errors.log and a GELF error. reraise defaults to False, so a decorated failure returns None unless the caller also has its own try/except.

consumer.py
Image entrypoint. Sequential poll, chunk, wait, sleep. SIGINT/SIGTERM. Secure Kafka when WORKER_ENV is production or stage.
consumer_queue.py
Queue + workers. Backpressure at QUEUE_MAX_SIZE. Commits after Popen. Test and priority filters. Graceful drain + poison pills.
consumer_batches.py
Batch or semaphore. USE_BATCHING (default true). 5s idle flush. USE_BATCHING=false starts a daemon thread per message limited by MAX_CONCURRENT_PROCESSES.
app/kafkaConsumeExecutor.py
The job. Filters, handlers, Redis, ParallelBatchHandler, row count, XLSX, email, Graylog timings. CLI --message.
app/messageHandler/
Contract of the Kafka JSON. EventPayload + field cleanup. Does not touch SQL.
app/queryHandler/ + queryParser.py
Templates to SQL. ID map, file load, Parser, column injection. Side-writes output.sql.
app/preprocessHandler/
Param rewrite by export id. Dates to ints, status expansion, numeric operator fragments, product column removals.
app/clickhouseHandler/
HTTP client + S3 function. Session id exp_{rand}_{ms}. split_query path replaces <full-file-path> placeholders. default_params (max_result_rows 180000, overflow break) are stored and not passed into get_client.
app/parallelBatchHandler/
Date slicing + combine HTTP. Only orders and order items. Fallback to first batch if combine fails.
app/rowCountHandler/
XLSX size check. Three count queries. skip_xlsx used; is_large_export unused by the executor.
app/excelConverterHandler/
CSV download → pandas → MinIO. Live path is _convert_to_xlsx_pd. Binary converter remains unused.
app/emailHandler/
MJML then send. Template email.eta.html, default Arabic body, logo at cdn.salla.network. SMTP definition shadows Mailgun/SES dispatch. Mailgun talks to api.eu.mailgun.net / salla.email with MAILGUN_KEY. SES needs SES_REGION, SES_ACCESS_ID, SES_ACCESS_SECRET. Optional EXPORTER_BCC_EMAIL.
app/redisHandler/
Lock then cache. REDIS_URL. Env-prefixed keys. Errors become “new”.
app/postgresHandler/
Lifecycle table. queued → running → combining → emailing → succeeded | failed. Never raises. Off without PG_HOST.
app/graylogHandler/
GELF. graypy UDP/TCP or HTTP POST /gelf. Typed helpers: info, email, error, processing, processing_info, websocket_activity, send_log.
app/errorHandler/
Singleton decorator. globalErrorHandler.error_handler. Step log on success; file + Graylog on failure; reraise off.
app/websocketHandler/
Written, not wired. Centrifugo-style POST /api, channel store_{id}_user_{id}, bilingual progress strings, WS_LOG_LEVEL default 0. Executor never imports it.
app/optimusHandler/
Written, not wired from the executor. Knuth multiplicative hashing, dual legacy/main configs from OPTIMUS_* env vars. Used only if WebSocket logs a terminal event.

10

Decisions the code made

These are visible in the repository as it is, including where later markdown disagrees with it. IMPLEMENTATION.md and MISSING.md describe an earlier cut. The executor already has parallel batching, Redis locks, Postgres types, row counts, Mailgun, and SES — and it also has the gaps below.

DecisionWhat the code does
Process isolation Every message is a new Python interpreter. Handlers, ClickHouse sessions, and MinIO clients are not reused across messages.
Push-down export ClickHouse writes CSV to S3. Python holds a URL, not the dataset — except during XLSX conversion, which downloads the whole CSV.
Dedup is parameters, not payload Same store + export id + params inside 15 minutes shares a file. Different recipients still share that cache key.
Continue on sidecar failure Postgres, Redis cache write, WebSocket, and combine-service errors are logged. Combine failure degrades to a partial file rather than failing the email.
Test traffic is inverted by env Production refuses tests. Development and stage refuse non-tests. That filter lives in the executor (always) and in the queue consumer (before spawn).
latest, not earliest A new consumer group ignores the backlog.
Secure Kafka only in named envs PLAINTEXT unless WORKER_ENV is production or stage.
Email send currently SMTP A second send_email definition wins. Local compose therefore matches MailHog; Mailgun/SES need that shadowing removed before they can run from the executor.
Progress UI not connected WebSocketPublisher and Optimus are complete modules. kafkaConsumeExecutor does not call them, so merchants do not get in-app steps from this process.
Batching ≠ row-count “large” 24-way split is by export id and dates, not by the 30 000-row flag computed afterwards.
Capture does not re-raise Decorated handler errors can vanish into Graylog while the executor proceeds with None, unless a surrounding try/except sees a later TypeError.

NameError on CH log

clickhouseHandlerClass.py calls logger.info without creating a logger. The first successful write path logs the S3 URL after the insert; that line raises if it is reached.

Hardcoded bucket in XLSX

ClickHouse uses S3_BUCKET. ExcelConverterHandler is constructed with s3_bucket = "exports" in the executor.

Default body is Arabic

get_body_text is a single Arabic sentence interpolating the subject. locale on the payload is not consulted for that string. The MJML template is direction="rtl".

A message, as the code sees it

Shape from EventPayload plus the live field the consumers read (not on the Pydantic model — extra keys are ignored there).

  "to": ["merchant@example.com"],
  "body": null,
  "user_id": 12345,
  "priority": 1,
  "locale": "ar",
  "parameters": {
    "store_id": 67890,
    "from_date": "2026-01-01",

  "bgColor": "#5dd5c4",

With that payload the executor would: pass filters (if not in development without is_test), lock Redis, split January into 24 ClickHouse exports, combine, count rows, skip or run pandas XLSX, render MJML, SMTP the link, cache it for 15 minutes.

email-exporter-consumer-python — a Kafka consumer that exports ClickHouse query templates to S3-compatible storage and emails a download link. Drawn from the Python sources, Dockerfile, compose file, and GitHub workflows — not from IMPLEMENTATION.md where that file lags the code.

No values from .env. Secret names only where the code reads them.
