TinoTesting / Trino 455 · Docker · six catalogs

How catalogs are wired,
and where a query goes

A single-node Trino coordinator on Docker, pointed at a Hive Metastore, MinIO, PostgreSQL and ClickHouse. Catalogs are property files. The query path is catalog name → connector SPI → metadata plane → storage plane.

01

The shape of the system

README is one line: set up Trino on Docker with multiple connectors. The running topology is docker-compose.yml. Six files under catalog/ become six Trino catalogs. Two other property files sit at the repo root and are not mounted.

Three facts about this shape drive everything that follows:

Catalogs are files, not a registry

Compose mounts ./catalog to /etc/trino/catalog. Filename minus .properties is the catalog name a SQL client uses. Changing a connector means editing a file and restarting Trino.

Two storage planes, one engine

Lakehouse catalogs (Hive, Iceberg, Delta, the extra Hive catalog named minio) share Hive Metastore + MinIO. JDBC catalogs talk straight to PostgreSQL and ClickHouse. Trino federates; it does not copy.

Coordinator is also the worker

coordinator=true and node-scheduler.include-coordinator=true. There is no separate worker service. Heap is -Xmx1G. Discovery points at http://localhost:8080 inside the container.

03

Catalogs and connectors

Each file in catalog/ is one catalog. The property connector.name selects the plugin. Everything else is connector config. Four catalogs share the same Hive Metastore URI thrift://hive-metastore:9083.

Catalog Connector Metadata Storage / JDBC Notes from the file
hive hive HMS Thrift 9083 MinIO http://minio:9000, path-style hive.security=sql-standard. Cache TTL 0s, refresh 5s, hive.metastore-timeout=10s.
minio hive HMS Thrift 9083 Same MinIO endpoint No hive.security. Timeout key is hive.metastore.thrift.client.read-timeout=10s (different property name from hive).
iceberg iceberg HMS Thrift 9083 Same MinIO endpoint Cache TTL 0s, refresh 5s, Thrift read timeout 10s. Table format is Iceberg; HMS holds the catalog.
delta_lake delta_lake HMS Thrift 9083 Not set in this file Only two keys: connector name and metastore URI. No hive.s3.*. A table whose location is s3://… has nowhere configured to open that path.
postgresql postgresql Postgres itself jdbc:postgresql://postgres:5432/trino_db User from connection-user. Password is in the catalog file — treat as a secret; do not commit real ones.
clickhouse clickhouse ClickHouse itself jdbc:clickhouse://clickhouse:8123/default HTTP interface, not the native protocol. Database name in the URL is default; compose also creates default_db.

Root files that are not catalogs

delta.properties repeats connector.name=delta_lake and the HMS URI — same idea as catalog/delta_lake.properties, but it is not under the mounted catalog directory, so Trino never loads it. storage.properties declares connector.name=storage and MinIO S3 keys. Same problem: it lives at the repo root, not in catalog/, and the storage plugin is not copied into plugin.dir.

04

The query path

Six stages. The fork is at catalog resolution: lakehouse queries go HMS then MinIO; JDBC queries never leave the target database; the in-repo storage plugin, if it were installed, would treat the schema as a file format and the table name as a path.

01

Client hits Trino

engine

HTTP on 8080, published to the host. Config sets http-server.process-forwarded=true so a reverse proxy that terminates TLS (the comment names Katacoda) is treated as secure. There is no password authenticator in etc/ — the node is open on the Docker network.

02

Analyze against a catalog

engine

Qualified names are catalog.schema.table. Trino loads every *.properties from /etc/trino/catalog at startup. Node identity is node.environment=docker, data dir /data/trino, plugins /usr/lib/trino/plugin. Logging is io.trino=DEBUG.

03

Lakehouse: metadata from HMS

hive · iceberg · delta · minio

Connector asks Hive Metastore over Thrift for databases, tables, partitions, and locations. HMS reads its own store from MariaDB (jdbc:mysql://mariadb:3306/metastore_db in metastore-site.xml). Cache TTL is zero on Hive and Iceberg so listings are not stale — at the cost of a Thrift round trip on every metadata call.

Iceberg still uses HMS as the catalog implementation here (hive.metastore.uri), not a REST or JDBC Iceberg catalog.

04

Lakehouse: bytes from MinIO

s3 path-style

Hive and Iceberg catalogs set hive.s3.endpoint=http://minio:9000 and hive.s3.path-style-access=true. Path-style is required: MinIO does not serve virtual-hosted bucket URLs the way AWS S3 does. HMS is given the same endpoint via Hadoop fs.s3a.* so location URIs it stores can be opened.

Gap — Delta Lake catalog/delta_lake.properties never sets those S3 keys. Metadata can resolve; object reads against MinIO are not configured in that catalog.
05

JDBC: pushdown to the database

postgresql · clickhouse

PostgreSQL uses the standard Trino PostgreSQL connector and a JDBC URL on the Docker hostname postgres. ClickHouse uses the HTTP port 8123. Compose publishes ClickHouse 9009 (interserver) and comments out native 9000 so MinIO can own that port on the host.

These catalogs do not share HMS. Cross-catalog SQL (SELECT … FROM hive.x JOIN postgresql.y) is planned in Trino and executed as two scans plus a join on the coordinator.

06

Pages on the coordinator

1G heap

Because the coordinator is in the worker pool, splits run in the same JVM that answered HTTP. JVM flags: G1, 32M regions, 256M reserved code cache, exit on OOM, dump heap on OOM. That is enough for lab queries; it is not a production worker profile.

05

The storage plugin in the tree

Under storage/ is the org.ebyhr.trino.storage connector (Trino Storage). It is source, not a running catalog. StoragePlugin registers one factory named storage — matching storage.properties. Compose never copies this into /usr/lib/trino/plugin.

Path routing in StorageClient.getInputStream: http:// / https:// go through Airlift HttpClient; hdfs://, s3a://, s3:// go through HdfsFileSystemFactory (S3 module wired in the factory); anything else is a local file and is denied if allow-local-files is false. Listing over HTTP is rejected. 

-- intended shape, once the plugin is on plugin.dir and
-- storage.properties is copied into catalog/
SELECT * FROM TABLE(storage.system.read_file(
    TYPE => 'csv',
    PATH => 's3a://bucket/path/file.csv'
));

SELECT * FROM TABLE(storage.system.list(
    PATH => 's3a://bucket/prefix/'
));
06

Node, JVM, metastore XML

etc/ is what the Trino container sees as its etc tree. conf/metastore-site.xml is what the Hive Metastore container sees. They agree on hostnames on the compose network.

etc/config.properties

  • coordinator=true
  • node-scheduler.include-coordinator=true
  • http-server.http.port=8080
  • discovery-server.enabled=true
  • discovery.uri=http://localhost:8080
  • http-server.process-forwarded=true

etc/node + jvm + log

  • node.environment=docker
  • node.data-dir=/data/trino
  • plugin.dir=/usr/lib/trino/plugin
  • -Xmx1G, G1, 32M regions
  • ReservedCodeCacheSize=256M
  • io.trino=DEBUG

conf/metastore-site.xml

  • Thrift URI hive-metastore:9083
  • JDO driver com.mysql.jdbc.Driver
  • JDBC URL host mariadb, db metastore_db
  • fs.s3a.impl = S3AFileSystem
  • s3a endpoint http://minio:9000
  • path-style access true

etc/user.properties is a duplicate of etc/node.properties (same three keys). It is not a user mapping file. Trino will ignore it unless the process is told to read that name.

Hive Metastore will still try to open MySQL on hostname mariadb. That hostname is not a service in docker-compose_no.yml. The Postgres metastore on 5433 is unused unless the XML driver, URL, and user are changed to match.

08

Decisions visible in the files

Single node, not a cluster

Coordinator schedules work onto itself

One Trino service, include-coordinator=true, 1G heap. Correct for a laptop lab. Wrong if anyone expects isolation between HTTP handling and scans.

Shared HMS for three table formats

Hive, Iceberg and Delta all use the same Thrift URI

One MariaDB-backed metastore is the catalog for Hive tables, Iceberg tables and (intended) Delta tables. That is a valid HMS-catalog layout. Namespaces are not isolated — a database created through hive is visible to iceberg as HMS metadata, even if the table format then disagrees.

Path-style S3 against MinIO

Virtual-host buckets would miss

Every S3 client in the repo sets path-style access and a path-style endpoint http://minio:9000. Hive catalogs, Iceberg, the unused storage.properties, and HMS fs.s3a.* all agree. That consistency is load-bearing.

ClickHouse over HTTP, not native 9000

Port 9000 belongs to MinIO on the host

Compose comments the ClickHouse native port mapping. The catalog JDBC URL uses 8123. That is a host-port decision, not a protocol preference inside the Docker network — containers could still talk 9000 to each other if the catalog said so. It does not.

Two Hive catalogs, one backend

hive vs minio

Same connector, same HMS, same S3 endpoint. Difference: SQL-standard authorization on hive, and a different metastore timeout property name. Useful as an alias; misleading if read as “the MinIO catalog is a different store.”

Metastore cache disabled

TTL 0s, refresh 5s

Hive and Iceberg catalogs do not cache HMS listings. Fine for a lab where another process is writing tables. Extra Thrift load if the catalog is large.

Plugin source without a mount

trino-storage is documentation-by-source

To actually query files as tables you would build the plugin, drop it in plugin.dir, and move storage.properties into catalog/. None of that is in compose.

Open HTTP, lab credentials in files

No authenticator, secrets in compose and catalogs

This is a local lab. Catalog JDBC passwords and MinIO keys are committed as placeholders. Do not reuse those values, and do not publish the host ports past localhost without adding auth.

09

What each path is for

docker-compose.yml
The topology that matches the XML. Trino 455, MariaDB HMS, MinIO, Postgres, ClickHouse.
docker-compose_no.yml
Alternate topology. Latest Trino on 8086, Postgres as intended HMS DB — currently inconsistent with metastore-site.xml.
catalog/*.properties
Live catalogs. Mounted to /etc/trino/catalog. Six connectors as named above.
etc/
Trino node config. Mounted to /usr/lib/trino/etc. Coordinator, JVM, logging, node id. Official images often also read /etc/trino — this mount is the one compose declares.
conf/metastore-site.xml
Hive Metastore overlay. Thrift, MySQL JDO, s3a to MinIO. Shared by both compose files.
delta.properties
Not loaded. Root-level duplicate of the Delta catalog idea.
storage.properties
Not loaded. Would enable connector.name=storage against MinIO if the plugin were installed and this file lived in catalog/.
storage/
ebyhr Trino Storage SPI. Factory, metadata, splits, page/record sources, file-type plugins, list / read_file table functions.
README.md
Intent only. “Setup Trino on docker and setup multiple connectors with it.”

Drawn from docker-compose.yml, docker-compose_no.yml, catalog/, etc/, conf/metastore-site.xml, storage/, and the two root property files. Object-store blob contents were not read. Catalog and compose credential values are omitted on purpose; only property names and hostnames appear here.
